----1. SQL (Structured Query Language)
🔹 What it is:

SQL is a standard programming language used to manage and interact with databases.

It is not software, but a language — used in many database systems (like MySQL, Oracle, SQL Server, PostgreSQL, DB2, etc.).

🔹 What you can do with SQL:

Create and manage databases

Insert, update, delete data

Retrieve data using queries
Example:
SELECT name, age FROM students WHERE age > 18;

-----What is a Cloud Server?

A cloud server is a virtual server that runs on a cloud platform instead of your local computer or a physical machine in your office.
It is hosted by cloud providers like Amazon Web Services (AWS), Google Cloud Platform (GCP), Microsoft Azure, etc.
Cloud Server for SQL and MySQL
Both SQL Server and MySQL can be hosted on the cloud.
1. Cloud Server for SQL (Microsoft SQL Server)

SQL Server (by Microsoft) is a relational database management system (RDBMS).

When hosted on the cloud, it becomes Azure SQL Database (Microsoft’s cloud version).

🔹 Features:

Fully managed by Microsoft (no need to install or maintain servers)

Automatic backup, scaling, and patching

Secure access and encryption

Pay only for what you use

*Cloud platforms that support SQL Server:

Microsoft Azure SQL Database → Microsoft’s own cloud SQL service

Amazon RDS for SQL Server → Managed SQL on AWS

Google Cloud SQL for SQL Server → Managed SQL on GCP

 2. Cloud Server for MySQL

MySQL is an open-source RDBMS widely used in web apps.

Cloud hosting lets you run MySQL databases without managing physical hardware.

🔹 Features:

Automatic backups

Easy scaling (increase/decrease storage or CPU)

High availability and replication

Web-based management tools

*Cloud platforms that support MySQL:

Amazon RDS for MySQL (AWS)

Google Cloud SQL for MySQL (GCP)

Azure Database for MySQL (Microsoft Azure)

Oracle Cloud MySQL Database Service



----What is a Connection?

A connection is a link between your application and a database.

When your app (like a Python, Java, or web app) needs to read or write data in a database (like MySQL, SQL Server, or PostgreSQL), it first has to connect to that database.

*Example:

Imagine your app is a student portal and the database stores student records.
When a student logs in:

The app connects to the database.

It fetches the student’s data.

Then it closes the connection.

---What is Connection Pooling?

Connection pooling means reusing database connections instead of creating a new one every time.

Creating a new connection is slow and uses a lot of resources (CPU, memory).
So, instead of opening and closing connections repeatedly, the app keeps a pool (collection) of ready-to-use connections.

When a user request comes:

The app takes a connection from the pool.

Uses it to query the database.

Returns it to the pool for reuse.

-----Difference Between DDL and DML
| **Feature**       | **DDL (Data Definition Language)**                               | **DML (Data Manipulation Language)**                    |
| ----------------- | ---------------------------------------------------------------- | ------------------------------------------------------- |
| **Purpose**       | Defines the **structure** of the database (tables, schema, etc.) | Used to **manipulate** or **change data** inside tables |
| **Affects**       | Database **structure**                                           | Table **data (records)**                                |
| **Examples**      | `CREATE`, `ALTER`, `DROP`, `TRUNCATE`, `RENAME`                  | `SELECT`, `INSERT`, `UPDATE`, `DELETE`                  |
| **Auto Commit**   | Automatically saves changes                                      | Needs **COMMIT** or **ROLLBACK** to save or undo        |
| **Used By**       | Database administrators                                          | Developers / users handling data                        |
| **Reversibility** | Usually **not reversible** once executed                         | Can be **reversed** using `ROLLBACK` before commit      |
| **Example Query** | `CREATE TABLE Students (id INT, name VARCHAR(50));`              | `INSERT INTO Students VALUES (1, 'Rahul');`             |

-----What is BIOS?

BIOS stands for Basic Input/Output System.
It is a built-in program stored in the computer’s ROM (Read Only Memory) that helps your computer start up and load the operating system.
How BIOS Works (Step-by-Step)

Let’s go step by step 👇

*Power ON

You press the power button.

BIOS starts running from the ROM chip on the motherboard.

* POST (Power-On Self Test)

BIOS checks whether important hardware (like CPU, RAM, keyboard, hard drive, etc.) is connected and working.

If there’s a problem, it shows error beeps or messages.

* Boot Loader Execution

Once hardware is okay, BIOS finds the boot device (hard disk, SSD, USB, etc.).

It loads the bootloader (like GRUB or Windows Boot Manager).

* Operating System Loads

The bootloader then loads the operating system (OS) into RAM.

Control is handed over from BIOS → OS.
**Functions of BIOS
| **Function**                  | **Description**                                                                   |
| ----------------------------- | --------------------------------------------------------------------------------- |
| **POST (Power-On Self Test)** | Checks if all essential hardware is working properly                              |
| **Bootstrap Loader**          | Finds and loads the operating system                                              |
| **BIOS Setup Utility**        | Lets you change system settings (boot order, time, date, etc.)                    |
| **CMOS Setup**                | Works with CMOS memory to store settings like date/time                           |
| **Driver Support**            | Provides low-level drivers for keyboard, display, and disk before OS drivers load |
Where is BIOS Stored?

BIOS is stored on a small ROM chip located on the motherboard of the computer.

That’s why even if you remove the hard disk, you can still access the BIOS setup screen.

-----why we use only 1024 not 1025?
We use 1024 (not 1025) because computers work in binary (base 2) — not in decimal (base 10).
And 1024 = 2¹⁰, which is a perfect binary number.
1️⃣ Computers Understand Binary

Computers don’t count like humans (1, 2, 3, 4...).
They use binary digits — 0s and 1s.

So, all computer memory and data sizes are based on powers of 2:
| Power of 2 | Binary Value | Decimal Equivalent |
| ---------- | ------------ | ------------------ |
| 2⁰         | 0000000001   | 1                  |
| 2¹         | 0000000010   | 2                  |
| 2²         | 0000000100   | 4                  |
| 2³         | 0000001000   | 8                  |
| ...        | ...          | ...                |
| **2¹⁰**    | 10000000000  | **1024**           |
2️⃣ Why 1024?

Because 2¹⁰ = 1024 is the closest binary number to 1000.

That’s why computer scientists started using 1 kilobyte (KB) = 1024 bytes —
even though, in normal decimal counting, “kilo” means 1000.
Example: Memory and Storage:
| Term | Binary Definition                   | Decimal Equivalent |
| ---- | ----------------------------------- | ------------------ |
| 1 KB | 2¹⁰ bytes = **1024 bytes**          | ≈ 1000 bytes       |
| 1 MB | 2²⁰ bytes = **1,048,576 bytes**     | ≈ 1 million bytes  |
| 1 GB | 2³⁰ bytes = **1,073,741,824 bytes** | ≈ 1 billion bytes  |
3️⃣ Why Not 1025?

1025 = 2¹⁰ + 1, which is not a perfect binary power.

Computers and memory addressing work in powers of 2 —
so 1025 would break the binary alignment.

It’s like having a box that holds 2, 4, 8, 16, 32 items…
you wouldn’t suddenly make a box that holds 33 — it doesn’t fit the binary pattern



-----What is Space Complexity?

Space Complexity is the amount of memory (space) a program or algorithm uses while running — based on the size of the input.
Components of Space Complexity:
| **Component**       | **Meaning**                                     | **Example**                                              |
| ------------------- | ----------------------------------------------- | -------------------------------------------------------- |
| **Input Space**     | Memory used to store the **input data**         | If input array = [1,2,3], it takes memory for 3 elements |
| **Auxiliary Space** | **Extra or temporary memory** used by algorithm | Temporary variables, recursion stack, etc.               |
Space Complexity=Fixed Part+Variable Part

Fixed Part → Constant memory used (for variables, constants, etc.)

Variable Part → Depends on input size (like arrays, recursion stack, etc.)
